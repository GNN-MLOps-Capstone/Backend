## 4. 구현 변경 사항

테스트 작성 과정에서 발견된 문제를 수정하거나, 테스트 환경 구성을 위해 실제 소스 코드를 함께 변경한 내역입니다.

### 4-1. `conftest.py` — 테스트 픽스처 전면 재구성

| 항목 | 내용 |
|------|------|
| **변경 유형** | 수정 (+31 / -13) |
| **핵심 변경** | `db_session` 픽스처를 트랜잭션 격리 방식으로 재설계 |

**변경 이유:** 기존 픽스처는 테스트마다 세션을 새로 생성·롤백하는 단순 구조였으나, 통합 테스트에서 실제 PostgreSQL 연결이 시도되거나 테스트 간 데이터가 오염되는 문제가 발생했습니다.

**주요 변경 내용:**
- `db_session`을 `join_transaction_mode="create_savepoint"` 방식으로 변경하여 각 테스트가 savepoint 단위로 격리되도록 수정
- `patch_async_session_local` 픽스처 신규 추가: `app.database.AsyncSessionLocal`, `onesignal_service`, `news_tasks` 등 실제 DB 연결 지점을 테스트용 세션으로 일괄 패치
- `NullPool` import 추가 및 `unittest.mock.patch`, `AsyncMock` 활용

---

### 4-2. `app/main.py` — APScheduler 초기화 위치 변경

| 항목 | 내용 |
|------|------|
| **변경 유형** | 수정 (+2 / -3) |
| **핵심 변경** | `AsyncIOScheduler` 인스턴스 생성을 모듈 최상단 → `lifespan` 함수 내부로 이동 |

**변경 이유:** 모듈 최상단에서 `AsyncIOScheduler`를 생성하면 테스트 실행 시 앱 import 단계에서 스케줄러가 초기화되어 테스트 환경과 충돌이 발생했습니다. `lifespan` 내부로 이동하여 실제 서버 기동 시에만 초기화되도록 수정했습니다.

---

### 4-3. `app/routers/stocks.py` — SQL 호환성 수정

| 항목 | 내용 |
|------|------|
| **변경 유형** | 수정 (+2 / -2) |
| **핵심 변경** | PostgreSQL 전용 문법을 표준 SQL로 교체 |

**변경 내용:**
- `COUNT(...)::numeric` → `CAST(COUNT(...) AS NUMERIC)`: PostgreSQL 캐스팅 문법을 표준 SQL로 변경
- `BTRIM(k.word)` → `TRIM(k.word)`: PostgreSQL 전용 함수를 표준 SQL 함수로 변경

**변경 이유:** 테스트 환경이 SQLite 인메모리 DB를 사용하기 때문에 PostgreSQL 전용 문법이 실행 오류를 유발했습니다. 표준 SQL로 교체하여 양 환경 모두에서 동작하도록 수정했습니다.
